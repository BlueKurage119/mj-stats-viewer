# UI検証依頼: Issue #5 アプリシェル（ルーティング・タブナビ・レイアウト骨格）

- **依頼日**: 2026-08-23
- **対象ブランチ / コミット**: `feat/issue-5-app-shell` / `c489a30`
- **所要時間の目安**: 約 15 分（うち実機スマホ確認 5 分）
- **なぜ逆発注するか**: Claude Code のブラウザペインは `document.visibilityState === "hidden"` のため Web Animations が進行せず、タブ切替モーションと層状シートのスクロール体感を**再生された状態で見ることが原理的にできない**。`prefers-reduced-motion` の切替も OS 設定依存で、実機（スマホ）の表示・タップ感も同様。DOM の値・CSS 変数・要素サイズ・ルーティング挙動は検収担当が機械測定済みで、本書には含めていない。

### V1. タブ切替モーションの方向が操作と一致しているか

4. 続けて「サマリー」（左端）をタップ／クリックする。同じく切り替わる瞬間を見る。

**期待結果**

手順3（右へ進む）ではカード層の中身が**右から左へ滑り込みながら**現れる。手順4（左へ戻る）では**左から右へ滑り込みながら**現れる。方向が逆に見えたり、どちらも同じ方向に見えたりしないこと。

**結果**（← ここを埋めてください）

- [ ] 不合格

## 対応記録（統括担当）

- **V1 / V3（タブ切替時にボトムツールバーが一瞬歪む・スクロールバーが出る）**: 実バグと確認。
  `TabTransition` の `translateX(24px)` アニメーション中、要素のバウンディングボックスが
  一瞬ビューポート幅を超え（375px→383pxを実測）、水平スクロールバーが出現→リフローで
  固定配置のボトムナビが揺れていた。`src/shell/shell.css` の `.layered-sheet__layer` に
  `overflow-x: hidden` を追加して修正（sticky ヒーローの挙動・C14/C15 相当の位置関係は
  修正後も維持されることを確認済み）。
- **S1（スクロールでカード層の上部がヘッダーに隠れる）**: 実装バグではなく、
  「ヘッダーは sticky・カード層は非 sticky」という設計どおりの挙動（sticky ヘッダーの下を
  コンテンツが通常どおり流れて隠れるのは一般的な挙動）。カード層を sticky 化して対処すると、
  将来コンテンツが1画面より長くなった際に**それ以上スクロールして続きを見られなくなる**
  副作用が生じるため、この Issue の範囲では対処しない。設計書 §9 に記載済みの
  「ヘッダーのスクロール連動エレベーション変化（M3 on-scroll app bar）は本Issue対象外・
  将来課題」と同一の論点として扱い、申し送りに留める。
- **S3（アプリバーとヒーロー領域を分けない方が自然かもしれない）**: 見た目の意匠に関する
  提案。ヒーロー領域の中身は本 Issue ではプレースホルダで、実際の中身は Issue #8
  （サマリー・カード1）が実装する。Issue #8 着手時に、この見た目のフィードバックを踏まえて
  ヘッダーとヒーローの視覚的な統合を再検討する。

対応差分: `src/shell/shell.css`（`.layered-sheet__layer` に `overflow-x: hidden` を追加）。
既存の受け入れ条件（A/B/C）は再実行し、全て通過を確認済み。
