### V3. メニューが実ブラウザで確実に開閉するか

エージェントの検証環境では `md-menu` の `closed` / `opened` イベントが発火しませんでした。**原因は特定済み**で、ブラウザペインのタブが `document.visibilityState === "hidden"` のため Web Animations API が進行せず、アニメーション完了を待つ両イベントが永久に解決しないというものです。ライブラリのバグでもコードの欠陥でもなく、実ブラウザの可視タブでは発火するはずですが、**その「はず」を実機で確認できていない**のでお願いします。

**操作**
1. `http://localhost:5173/#/__components` を開く
2. ページ内の「メニューを開く」ボタンを探してクリック
3. 開いたメニューから項目（「上位」など）をクリック
4. もう一度「メニューを開く」をクリック
5. 今度は項目を選ばず、メニューの**外側**をクリック

**期待結果**
- 手順2: ボタンの**すぐ下**にメニューが開く（ページ左上や画面端に飛ばないこと）
- 手順3: メニューが閉じ、「選択結果: 上位」のような表示に変わる
- 手順5: メニューが閉じる。続けてボタンを押すと**1回目のクリックで**再び開く（1回空振りして2回目で開く場合は不合格。上記の状態不整合が実ブラウザでも起きていることになります）

**結果**

- [X] 合格
- [ ] 不合格
- [ ] 判断保留

```
実際に見えたもの / 保留の理由:
手順5) 1度目で開いた。2度目は閉じた。
```

### S1. 段位4色の印象

**見るもの**: `#/__theme` の「段位」セレクタを 雀傑 → 雀豪 → 雀聖 → 魂天 と順に切り替える（light / dark 両方で）。

**背景**: 設計担当はコントラスト比を数値で満たすことを優先し、雀傑は「純黄はライトモードで必然的にオリーブに沈む」という制約から `#E6B422`（黄金系）を選んでいます。数値上の合格と、見た目の納得は別物です。

**問い**: 4つの色を切り替えたとき、それぞれから受ける印象を書いてください。段位の格の上下が色から伝わるか、あるいは伝わらないか。差し替えたい色があればそれも。

```
回答:
段位4色については現段階では問題ない。部品が揃った際に改めて全体のバランスで確認しよう。
セクションスウォッチは、セクション構成を検討した際に改めて色を考えても（もしくは色をつけなくても）いいのかもしれない。
```
