# UI検証依頼: Issue #7「最小検索導線」

- **依頼日**: 2026-08-23
- **対象ブランチ / コミット**: `feat/issue-7-search` / `682c3cf`
- **所要時間の目安**: 約 15 分
- **なぜ逆発注するか**: 日本語IMEの変換中イベント（`compositionstart` / `input` の `isComposing` / `compositionend`）は、エージェントが `dispatchEvent` で合成しても実際のIMEの発火順序を再現できない。本実装はIME分岐を意図的に入れず「デバウンス300msと文字列の同一性」だけで吸収する設計のため、変換中のちらつきと確定後の検索が実際にどう見えるかは人手でしか確かめられない。デバウンス時間・スケルトンの見え方・実機ソフトキーボードも同様に体感の問題で、機械測定では合否を出せない。

## 準備

```bash
git switch feat/issue-7-search
npm run dev
```

ブラウザで `http://localhost:5173/#/` を開く。トップに「ニックネーム」という検索ボックスが1つある画面が出る。

> 終わったら dev サーバーは Ctrl+C で停止してください。

**この画面の仕様（前提知識）**
- 入力を止めてから **300ミリ秒** 後に検索リクエストが飛ぶ（入力のたびには飛ばない）
- 検索中は灰色の長方形が **3行** 表示される（スケルトン）
- 検索結果の各行は「ニックネーム / 段位 / (別モードのときだけ 三麻・四麻のラベル) / 最終対局日」
- 右上の「四人打ち｜三人打ち」で検索対象を切り替える

## 対応記録（統括担当）

- **S3（長押しするとリップルが残ってしまう）**: `@material/web` の `md-ripple`
  （`node_modules/@material/web/ripple/internal/ripple.js`）自体の既知の挙動と確認した。
  タッチ操作では `pointerdown → HOLDING → pointerup → WAITING_FOR_CLICK` と遷移し、
  リップルを消す `endPressAnimation()` は最終的にネイティブの `click` イベントが
  発火して初めて呼ばれる。実機で長押しした際、OS/ブラウザがそれをタップではなく
  テキスト選択やコンテキストメニューの操作と解釈すると `click` が発火せず、
  `pointercancel`/`contextmenu` も飛ばないことがあり、リップルが視覚的に残る。
  同じ `<Ripple />` の使い方は Issue #5 でマージ済みの `NavigationRail` でも
  共通しており、Issue #7 固有の実装で新たに持ち込んだ不具合ではない。
  自前のラッパー（`src/components/md/Ripple.ts`）はライブラリへの薄いラップのみで
  独自ロジックを持たず、アプリ側の力技（タイムアウトで強制解除等）は正当な
  長押し操作を誤って中断するリスクがあるため、この Issue の範囲では対応しない。
  プロジェクト全体の Ripple 共通対応として別タスク化した
  （spawn_task: 「md-rippleの長押し残留を調査」）。マージの可否には影響しない。
