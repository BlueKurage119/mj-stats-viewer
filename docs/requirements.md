## 1. プロジェクト概要

雀魂牌譜屋（amae-koromo）のAPIデータを用いて、プレイヤーのスタッツをヒストグラム・グラフ中心に見やすくビジュアライズするWebアプリ。

- **対象**: 四麻・三麻の両対応（UI切替）
- **コンセプト**: 「あなたの成績は卓全体のどこか」を主役にした、OS純正ヘルスケアアプリ風のダッシュボード
- **差別化**: 本家がツールチップ内に隠しているヒストグラム比較を一覧で常時表示。段位点期待値・昇格/降格条件など本家にない指標

### 1.1 フェーズ区分

| フェーズ | データ源 | 内容 |
|---|---|---|
| **PoC（本要件）** | 認証不要エンドポイントのみ | サマリー・比較・スタッツの3タブ |
| **承諾後** | `player_records`（SAPikachu氏へキー申請後） | 直近n戦・対戦履歴タブ・1局粒度の順位グラフ |

`games` / `player_records` は2026-07よりCAP（PoW型CAPTCHA）保護下にあり、**迂回は行わない**（詳細: API仕様書 §2.3）。APIコールを増やす回避策（二分探索等）も採用しない。

| 日付 | dayjs | |

検証済み事項（2026-08-21）:
- React 19 + Vite + `@material/web` v2.5.0 で描画・クリック・状態連動まで動作確認
- タイポグラフィは `@material/web/typography/md-typescale-styles.css` を直import（JSエクスポートは廃止済み）

### 2.1 MUI不採用の理由

MUIはMD3非追従（`@mui/material-next` はalpha凍結）。React製MD3ライブラリ（actify等）は実質無メンテ。Google公式の `@material/web` が唯一の実用的なMD3実装（週11万DL・nightly更新継続中）。

## 3. デザイン方針

**Material 3 Expressive**（2025年発表、新Google Health / Fitbitアプリ準拠）を目標とする。

| 要素 | 方針 |
|---|---|
| レイアウト | **層状シート**: 上部に主要統計をテーマ背景で置き、スクロールでカード層がせり上がる |
| タイポグラフィ | 大きく強調された数値（emphasized type、Display/Headline級）。日本語フォントは Noto Sans JP 系を土台 |
| 配色 | シード色（叩き台: 雀卓グリーン `#1D6B4F`）からトーナルパレット生成。ライト/ダーク両対応 |
| セクション色 | 内容別テーマ色（叩き台: 和了=コーラル / 放銃=ブルー / 立直=パープル / 運=アンバー）。レーダー軸色と連動 |
| モーション | spring風トランジション、チャートは左→右アニメ、タブはshared-axis |
| ナビ | モバイル=ボトムナビ（labs/navigationbar）、デスクトップ=ナビレール |
| M3E新コンポーネント | コスト次第で従来コンポーネントで代替可（フローティングツールバー等は必須としない） |

「LLMに作らせた感」の排除: 既定テーマのまま使わない／スケルトンローディング／空・エラー状態の作り込み／紫グラデ・絵文字・中央寄せヒーロー等の手癖排除。

## 4. 画面構成

```
プレイヤーページ = [ヘッダー: 四麻/三麻切替]
                + [グローバルフィルタ: モード・期間]
                + [タブ: サマリー / 比較 / スタッツ / 履歴(将来)]
```

- 検索画面・トップ画面（プレイヤー未選択時）は**後回し実装**（本要件では最小限の検索導線のみ想定）
- 履歴タブは承諾後まで非表示

### 4.1 サマリータブ（5カード構成）

製品紹介ページ的なスタイリッシュさ。ヒストグラムは使わない（比較タブの役割）。

| # | カード | 内容 | ビジュアル |
|---|---|---|---|
| 1 | **アイデンティティ** | 名前・段位★・段位pt（`score+delta`）・昇段まで残pt・**昇格/降格条件**・順位グラフ(承諾後) | 大きな数値。**グローバルフィルタの影響を受けず常に現在**（全モード・全期間） |
| 2 | **成績** | 順位分布＋平均順位・連対率・ラス率・飛び率・平均持ち点 | 順位分布=ドーナツ、他=タイル |
| 3 | **打ち筋** | 攻守速制運レーダー＋傾向バー2本＋タイプ名見出し | レーダー＋5段階セグメントバー |
| 4 | **主要スタッツ** | 和了率・放銃率・立直率・副露率・平均打点・平均放銃点 | 6タイル（3×2）。卓平均との差分チップ（▲/▼）付き |
| 5 | **和銃分布** | 和了時の状態／放銃時の状態／放銃相手の状態 | ドーナツ3枚 |

- カード1の昇格/降格条件: 「1位なら昇格」「1位で◯点以上」「3位なら降格」等。表示条件はCLI版踏襲、**計算式は本家 `calculateDeltaPoint` 準拠に修正**（§6.4）
- カード2の導出: 連対率=上位2順位率の和、ラス率=最下位率、平均持ち点=Σ(順位率×順位別平均点)
- 成長指標はスタッツタブへ、段位分布は比較タブへ配置（サマリーには置かない）

### 4.2 比較タブ

本アプリの目玉。「自分 vs 全体」の分布比較を一覧表示。

```
[コンテキストバー(sticky)] 対象モード / 母集団n / 凡例(自分・卓平均・段位平均)
[段位分布カード]  levelId粒度の分布 + 自分ハイライト + 上位%   ← スコープE
[指標カード14枚]  カテゴリ見出しで区切り
```

| カテゴリ | 指標 |
|---|---|
| 率系(6) | 和了率・放銃率・立直率・副露率・ツモ率・黙聴率 |
| 打点系(5) | 平均打点・平均放銃点・打点効率・銃点損失・調整打点効率 |
| 速度(1) | 平均和了巡目 |
| 運(2) | 裏ドラ率・一発率 |

各カードの構成: 分布（bins 120本）＋自分マーカー＋卓平均線＋段位平均線＋大きな値＋**上位%チップ**。

- lowerIsBetter指標（放銃率・平均放銃点・銃点損失・平均和了巡目）は上位%の向きを反転し「良い方＝上位」で統一
- **単一モード制約**: 分布データはモード単位のため、グローバルフィルタが複数選択のときは**選択中モードのうち対局数最多を代表として自動採用**し、コンテキストバー内のチップで切替可能にする
- 母集団は常に全期間の全体分布（`global_histogram` は期間指定不可）。期間フィルタ適用時は「直近◯◯の自分 vs 卓全体」となる旨を注記

### 4.3 スタッツタブ

全指標の正確な一覧。先行して個人的に作成したCLI版ツールの章立てを踏襲:

```
順位分布 → 総合成績1 → 総合成績2 → 効率指標 → 成長指標
→ 立直統計 → 副露統計 → 和銃分布 → 幸運度
```

- MD3リスト形式: ラベル＋値＋**分母注記をサブテキストで常時表示**（例: ツモ率 36.54% "和了回数比"）。ツールチップに隠さない
- **成長指標**: 段位点期待値（pt/戦）・降段/昇段まで◯戦・50戦後の見込み・安定段位
- 日本語ラベルはCLI版準拠（黙聴率・平均和了巡目・痛い親かぶり率・雀傑★★等）
- 値0で省略される回数系キー（役満・数え役満・W立直・流し満貫・最大連荘等）は `?? 0` で補完

### 4.4 履歴タブ（承諾後）

対局履歴テーブル（日時・モード・順位・最終得点・段位pt変動・牌譜リンク）。CLI版の直近対局履歴と同形式。

## 5. フィルタ仕様

### 5.1 モードセレクタ（グローバル）

- 複数選択可・「全モード」可。APIは `mode=26.24.22...`（`.`連結）で複数モードを1リクエスト集計
- 既定値: **自分が入れる最上の卓**（levelId→LEVEL_ALLOWED_MODES。未プレイならplayed_modes中の最上位。半荘優先）
- 比較タブのみ単一化（§4.2）

### 5.2 期間フィルタ

- **プリセットのみ**: 全期間／1年／90日／30日／7日（`@material/web` に日付ピッカーが無いため、カスタム日付範囲は後回し）
- 1操作あたりAPIコール2回（player_stats + player_extended_stats）
- データなし期間はAPIが404（`id_not_found`）を返す → 「この期間の対局はありません」表示に変換
- **直近n戦は承諾後**: 本家と同じ2段階方式（`player_records?limit=N` で境界時刻特定 → 期間クエリ変換）。プリセットは本家準拠の100/200/300/500戦。データ取得層に範囲解決インターフェースを設け、承諾後に実装追加のみで対応できる構造にする

### 5.3 フィルタの適用範囲

| 対象 | モード | 期間 |
|---|---|---|
| カード1（段位・pt・昇降条件） | **常に全モード** | **常に現在まで全期間** |
| カード2〜5・スタッツタブ | 従う | 従う |
| 比較タブ（自分の値） | 代表単一モード | 従う |
| 比較タブ（母集団分布） | 代表単一モード | 常に全期間 |

理由: `player_stats` の `level` は「クエリ範囲内の最終対局時点のスナップショット」のため、絞り込むと過去の段位が返る（API仕様書 §4.5）。

## 6. 計算仕様

### 6.1 レーダーチャート（攻守速制運）

母集団: `global_histogram` の **band 0（卓全体）の histogramFull** から μ・σ を算出（段位帯はmeanのみでσ不可のため）。

| 軸 | 定義 |
|---|---|
| 攻 | 偏差値(打点効率) |
| 守 | **100 −** 偏差値(銃点損失) |
| 速 | 偏差値(和了率) |
| 制 | 偏差値(立直率) |
| 運 | **50 × (裏ドラ率+一発率) ÷ (卓平均裏ドラ率+卓平均一発率)**（卓平均=50の相対値） |

偏差値 = 50 + 10×(x−μ)/σ。σは **histogramFull 基準**（clampedはσ過小で偏差値が過大に出るため不使用）。

### 6.2 傾向2軸（5段階）— 叩き台

`yurakuurame/4ma-majang-type-check` の発想（z値合成による2軸スタイル分類）を、ハードコード定数ではなく `global_histogram` のライブμ・σで再構成する（三麻対応と自動更新のため。元リポジトリはライセンス表記なしのため定数は流用しない）。

| 軸 | z合成（係数は実装時に調整） | 5段階の例 |
|---|---|---|
| 攻⇔守 | z(立直率)+z(追っかけ率)+z(放銃率)−z(黙聴率) の平均 | 鉄壁/守備寄り/バランス/攻撃寄り/フルアタック |
| 門前⇔速度 | z(副露率)−z(黙聴率)−z(和了巡数)※逆向き の平均 | 門前主義/やや門前/バランス/やや鳴き/速攻全振り |

閾値: z=±0.5・±1.5 → 分布上おおむね 7/24/38/24/7% に割れる。タイプ名見出しは2軸の組合せから生成。

### 6.3 上位%（パーセンタイル）

histogramFull の bins 累積和を線形補間。lowerIsBetter指標は反転表示。

### 6.4 昇格・降格条件（カード1）

CLI版 `rankConditions.js` の表示ルールを踏襲しつつ、計算式を本家準拠に修正する。

```
段位Pt変動 = ceil((素点 − 配給原点)/1000 + 順位点) + モードボーナス − ラスペナ(最下位のみ)
  配給原点: 四麻25000 / 三麻35000
  順位点: 四麻[+15,+5,−5,−15] / 三麻[+15,0,−15]
  モードボーナス(MODE_DELTA)・ラスペナ(LEVEL_PENALTY系): 本家定義
```

**CLI版の既知バグ（要修正）**: ①モードボーナス欠落（昇段条件が過大に出る）②ラスペナ欠落（降段条件が過小に出る）。修正版は素点を走査して条件を満たす境界値を求める（ceilの扱いを正確にするため逆算式は使わない）。

### 6.5 成長指標

- 段位点期待値/戦 = Σ(順位率 × 順位別段位Pt変動)。順位別変動は rank_avg_score を §6.4 の式に代入
- 複数モード選択時は「入れる最上の卓・半荘」の表を基準に計算し、その旨を注記
- 降段まで◯戦 = 現在pt ÷ |期待値|（期待値<0時）／昇段まで◯戦 = 残pt ÷ 期待値（>0時）
- 50戦後見込み = 1戦ずつ期待値を適用する逐次シミュレーション。昇降段時、新ポイントは「新段位上限の1/2」にリセットする（本家 `getAdjustedLevel` 準拠）。当初案の「段位跨ぎは pt 表で線形換算」は本家実装と一致しないため訂正した。詳細・実測値は [docs/design/issue-4-domain-logic.md](design/issue-4-domain-logic.md) §1.4・§4.3 を参照
- 安定段位 = 本家 `estimateStableLevel2` 移植

### 6.6 その他の導出値

- 現在段位pt = `level.score + level.delta`（雀傑★★ 232/1400 形式。昇段点は LEVEL_MAX_POINTS）
- 局収支 = (Σ順位率×順位別平均点 − 配給原点) × 試合数 ÷ 局数（APIは返さないためクライアント計算・本家式）
- 和了/放銃相手の内訳% = 回数÷合計（ドーナツ用）
- 段位分布の自分の位置 = `level_statistics` を全zone合算 → 自分のlevelIdの累積%
- count 2種の使い分け: `player_stats.count`=試合数 / `player_extended_stats.count`=局数（表示で明示: 「134戦 / 1,151局」）

## 7. API利用方針

- ミラー4系統のフォールバック（5-data → 1/2/4.data）
- URL単位のメモリキャッシュ。過去期間の値は不変なので積極キャッシュ
- `{maintenance}` / `{result_key}` レスポンスへの対応（API仕様書 §2.2）
- `tag` パラメータは本家同様に付与（キャッシュバスト用途）
- **リクエスト節度**: 1画面表示あたり数リクエスト以内を目安。連打防止のdebounce。二分探索のような多量コール手法は使わない
- robots.txt の意向を尊重し、クロール的な一括取得は行わない

使用エンドポイント（すべて認証不要・実測確認済み）:
`search_player` / `player_stats` / `player_extended_stats` / `global_histogram` / `global_statistics_2` / `level_statistics`
